# 小米电视真机验证记录

验证设备：小米电视 6（MiTV-MFZP0），Android 9 / API 28，逻辑分辨率 1920×1080、320 dpi。守护独立运行，不修改 Aerial 桌面。

## 当前发布状态

- 守护版本 1.0.0，正式题库 1800 道；33 项 `testDebugUnitTest`、`lintRelease`、`assembleRelease` 通过，Release APK 已通过生产证书 v2 验签，电视安装包与构建产物 SHA-256 一致。
- 当前守护 APK SHA-256：`785421f4f3f5e3447abe01e851d1bf66b22cdc3edac07b2cc6f4c2f93472491b`；签名证书 SHA-256：`e29fee42adf56e5a8dbffd54a59f0438b3ea48554f83c49582c5e00a8756d1ee`。
- WebTV 1.2.1 的 `./scripts/verify.sh --offline` 通过，四个 Release 变体已构建并验签；目标 Android 9 设备使用 Gecko armeabi-v7a 包。
- 守护与 WebTV 1.2.1 已按相同生产证书安装，家长 PIN 已初始化，WebTV Debug 包已删除。旧 WebTV 使用不同证书，无法覆盖安装，替换前已备份旧 APK，但其私有设置无法保留。
- 第一次生产 5 分钟测试发现：守护服务重绑后只查询最近 60 秒前台事件，无法识别已经持续播放的 WebTV。已改为服务未取得前台包名时查询 24 小时引导事件，正常运行仍使用 60 秒窗口；修复后完整 5 分钟触发通过。
- 已定位答题层 `IllegalStateException`：`addView` 后、View 完成附着前的同步渲染重复添加同一个 View。修复后真机只保留一个全屏答题窗口，未再出现该异常。
- 第二次整机重启的 bootCount 从 317 变为 318；题目 `cn-327`、questionSerial 97、连续答错 2 题保持一致，冷却剩余时间从约 110 秒降至约 65 秒，重启后 ADB 当时自动恢复。
- 独立 ADB 保持功能已实测：手动设置 `adb_enabled=0` 并断开后，约 25 秒可重新连接，`adb_enabled=1`；该结果归因于本守护的看门狗，不归因于 Aerial。
- 最终包已移除临时状态、答案和家长入口诊断日志；PIN、300000 ms 触发配置和守护开关在覆盖安装后保持，`/setup` 返回 200，未授权配置读取返回 401。
- 小米 ROM 会在特定条件下强停同时保留初始化 Activity 与无障碍窗口的应用。初始化页现于显示期间移除答题层，退出时关闭 Activity 并延后恢复；最终版覆盖安装、退出初始化和遗留任务清理已复测，交付前任务状态为 `IDLE`。

## 生产版已观察到的结果

- 默认 300000 ms 配置下，WebTV 真实播放超过 5 分钟后触发答题，媒体会话进入暂停。
- 答错立即换题；连错两次进入 120 秒冷却；冷却中方向键和确认键不改变题目进度，倒计时结束恢复答题。
- 答题及冷却中按 Home 后，当前焦点和遮挡窗口仍为守护的全屏 Accessibility Overlay。
- 连续答对 3 题后回到 WebTV，媒体会话恢复 `STATE_PLAYING`，守护回到 `IDLE`、播放累计清零并重新计时。
- 单题 60 秒无操作会换题并累计一次连续答错；第二次超时进入冷却。
- 强停后重新初始化，题目 ID `cn-556`、questionSerial 12 和连续答错进度保持不变，答题剩余时间随经过时间减少。
- `/setup` 返回 200；未登录配置读取和错误 PIN 均返回 401；正确 PIN 登录成功；配置保存后重新读取一致，非法触发时长返回 400，退出后会话失效。

## 家长设置三项优化回归

- 手机网页 PIN 已改为六个独立密码格。浏览器实测首格接收完整 6 位输入后自动分格、六格均显示掩码，登录成功；逐格输入、退格、方向键及整段粘贴逻辑已做脚本语法检查。
- 设置页新增云视听极光和 WebTV 独立开关。云视听开关保存后 `/api/v1/apps` 状态随配置变化，随后恢复开启。
- WebTV 真实播放触发任务并进入冷却时，单独关闭 WebTV 并保存，诊断立即变为 `IDLE`，题目 ID 和冷却时间清空，云视听仍开启；窗口列表不再存在 `ty=2032` 答题层，WebTV 媒体状态恢复 `STATE_PLAYING`。继续真实播放 65 秒未再次触发。
- 再次真实触发 `QUIZ_ACTIVE` 后，关闭全局守护并保存，诊断立即变为 `IDLE`，题目及累计时间清零、答题层消失、媒体恢复播放。重新开启后未恢复旧题。
- ADB 自检页新增家长二维码入口，已实际生成二维码、识别入口并在浏览器登录，用于全局关闭后重新进入设置；后续已升级为固定长期地址。
- 本轮测试结束后恢复正式配置：全局及两个应用守护均开启、300000 ms 触发、连对 3 题、连错 2 次冷却 120 秒、单题 60 秒、自动恢复及前台估算开启；最终为 `IDLE`，无答题窗口。

## 固定家长入口回归

- `/setup` 直接返回 200；不含 `entryToken` 的固定地址可通过正确 PIN 登录，错误 PIN 返回 401，未授权配置接口仍需有效会话。
- 带旧 `entryToken` 参数的收藏链接打开后自动清理为 `/setup`，正确 PIN 登录成功；再次打开固定地址可恢复有效会话，会话过期后重新验证 PIN 即可。
- 答题页与 ADB 自检页二维码均已改为固定地址。真机生成二维码并解码确认路径为 `/setup`、无查询参数，不再包含 2 分钟有效令牌。
- 页面显示当前电视的固定局域网地址及收藏提示；固定地址以电视 IP 不变为前提，不宣称跨 IP 变化仍可访问。
- 13 项单元测试、Release Lint、正式 APK 构建和 v2 验签通过；电视实际安装包与构建产物 SHA-256 一致，原守护规则及两个应用开关均保持开启。

## 云视听前台识别与真实暂停修复回归

- 修复前云视听窗口和音频轨均正常，但守护诊断中的前台包名被 `com.xiaomi.mitv.systemui` 覆盖，有效播放累计停在 `86254 ms`，因此无法达到 `300000 ms` 触发阈值。
- 无障碍事件及 UsageEvents 查询现统一忽略 `com.android.systemui`、`com.mitv.systemui`、`com.xiaomi.mitv.systemui` 三类临时系统界面；桌面和其他普通应用仍作为真实前台切换处理。新增 3 项策略单元测试，总计 16 项测试通过。
- 保留电视已有累计进度，将触发阈值临时改为 `60000 ms` 后覆盖安装修复包；约 8 秒内云视听上实际出现全屏答题层，当前焦点转为守护，诊断前台保持 `com.ktcp.video`、阶段为 `QUIZ_ACTIVE`。
- 随后恢复 `300000 ms` 正式配置，云视听重新累计并达到 `300775 ms` 后自然触发答题。全局和云视听守护开启；WebTV 独立开关按用户当前选择保持关闭。
- 音量加、减操作后，系统窗口和守护诊断均保持云视听为真实前台；媒体音频活跃时累计时间继续增长。
- 进一步实测发现，部分云视听片源在守护取得音频焦点后仍保持 `started`，因此不能把取得焦点或调低音量视为真实暂停。临时静音试验代码已全部移除，最终版本不修改媒体音量。
- 新增无桌面入口的 `PlaybackPauseActivity`，在答题层后让云视听 Activity 进入后台生命周期，同时保留音频焦点请求。真机观察到原音频轨依次进入 `paused`、`stopped`、`released`，当前播放器列表中不再存在云视听播放轨。
- 小米 ROM 会在带无障碍窗口的 Activity 切到后台时强停应用。最终版在 `PlaybackPauseActivity.onPause` 中先移除答题层，再延后恢复 Activity 和答题层；复测 Home 后 `ty=2032` 和暂停 Activity 均存在，云视听仍无播放轨，音量保持 18。
- 家长解除本轮后，答题层和暂停 Activity 均退出，云视听回到前台并出现新的 `started` 音频轨；守护回到 `IDLE` 重新累计，300000 ms 正式配置保持不变。

## 诊断、冷启动、答案反馈与错题集回归（2026-11-14）

- 家长诊断页不再直接输出格式化 JSON，改为中文指标行。375×812 手机视口实测显示 21 行指标，`innerWidth`、页面 `scrollWidth` 均为 375 px，诊断区宽 302 px；长媒体状态会换行，无横向溢出。
- 针对关闭电视一段时间后首次使用可能不计时的问题，前台恢复现在同时接收窗口状态与窗口集合变化；服务重绑、守护自身窗口或非受控应用缓存状态下会按 30 秒间隔重新查询 24 小时 UsageEvents 引导记录，正常受控播放仍使用短窗口，避免高频长查询。
- 最终生产包完成两次整机重启检查。有效测试在确认配置落盘后进行：重启后首次启动云视听并真实播放，未打开手机设置或诊断页，累计 `60508 ms` 后自动进入 `QUIZ_ACTIVE`，说明冷启动链路无需家长页面唤醒。
- 数学题 `ma-138` 答错后，所选项显示红色“你的选择”，正确项显示绿色“✓ 正确答案”；反馈期间连续发送方向键、确认键和返回键均未跳题，阶段保持 `ANSWER_FEEDBACK`，约 6 秒后才进入下一题。第一题答错后错题数为 1。
- 第二次超时答错同样先进入答案反馈，再进入 120 秒冷却，而非直接跳过反馈；冷却结束恢复答题。反馈阶段也纳入配置关闭、开机恢复、时钟持久化及 Home 返回逻辑。
- 错题策略新增 8 项专项测试，覆盖 65% 错题池权重、错题提前重复、答错加入、答对移出并锁定、本科目全覆盖后解锁、科目独立轮转、最近题避让和 JSON 持久化；反馈阶段新增 3 项规则测试，总计 27 项单元测试通过。答对移出错题集属于单元规则验证，本轮真机连续答对的三题均为普通题，不冒称已真机观察错题数下降。
- 真实暂停回归中，云视听音频轨由 `started` 进入 `paused/stopped/released`；连续答对 3 题后返回云视听并重新累计播放。关闭全局守护保存会立即退出答题层并释放暂停状态。
- 测试后已恢复用户当前正式配置：全局与云视听开启、WebTV 关闭、触发 `600000 ms`、连对 3 题、连错 2 次冷却 120 秒、单题 60 秒、自动恢复及前台估算开启；最终为 `IDLE`，无答题窗口。

## 后台强停与自动重绑防护回归（2026-11-14）

- 故障现场守护进程不存在、`/setup` 不可达，包状态为 `stopped=true`，学习守护已从 `enabled_accessibility_services` 移除，而通知监听授权和其他应用的无障碍服务仍在。近期崩溃缓冲区无守护异常；该状态符合后台强停及绑定被移除，但没有保留足够的早期系统日志，不能进一步断言具体系统组件。
- 保留原配置的初始化流程恢复后，服务立即接管云视听，并恢复中断前 `QUIZ_ACTIVE` 任务。用户当时调整的连对 4 题、单题 90 秒、答错反馈 15 秒均保持，未重置 PIN 或学习记录。
- 初始化新增 `RUN_IN_BACKGROUND`、`RUN_ANY_IN_BACKGROUND`、活跃待机分组及 `deviceidle` 白名单。新增独立低优先级前台 `GuardWatchdogService`，普通进程回收使用 `START_STICKY`，每 30 秒检查并合并恢复无障碍绑定，开机和服务连接时启动；未修改 Aerial。
- 真机临时从系统设置移除学习守护的无障碍组件，18 秒后自动恢复，PID 28820 不变，其他 3 个无障碍服务全部保留。随后诊断确认云视听前台、音频活跃及播放累计正常，家长配置未改变。
- 本轮新增 3 项服务列表合并测试，总计 32 项单元测试、Release Lint、正式构建及 v2 验签通过；无损拉取安装包与构建产物 SHA-256 一致。当时的前台检查只能降低后台回收概率并修复运行中的解绑，不能处理整机强停；本次新增的 SyncAdapter 系统侧唤醒见下节。

## 强停后系统同步唤醒回归（2026-11-15）

- 新增独立本地账户及 `settings` authority 的 SyncAdapter，不上传账户、题目、媒体或其他用户数据。系统设置变化会调度同步，SyncManager 可绑定已强停的应用；同步回调重新启动前台守护、ADB 保持并合并恢复无障碍及通知监听授权，随后按需重绑无障碍服务。未修改 Aerial。
- 19:00 从正常状态记录 PID 16266，直接执行 `am force-stop com.icybard.learningguard`，期间未再次运行初始化。约 29 秒后自动出现新 PID 16495，守护组件回到无障碍列表且 `/setup` 返回 200；其他 3 个无障碍服务完整保留。随后诊断为 `serviceConnected=true`、包状态 `stopped=false`。
- 另做 45 秒短时熄屏检查，唤醒前后 PID 均为 16495，无障碍绑定与设置接口正常。该结果只证明本次短时场景，不承诺覆盖所有长期待机或未来系统升级。
- 自动恢复后保留用户正式配置：全局与云视听开启、WebTV 关闭、触发 `600000 ms`、连对 4 题、连错 2 次冷却 120 秒、单题限时 90 秒、答错反馈 15 秒、自动恢复及前台估算开启；未清空 PIN、错题或学习记录。

## 媒体适配说明

- 这台小米 ROM 的通知监听发现机制不能可靠提供媒体会话，因此 WebTV 使用带签名权限的显式绑定服务，直接提供 `MediaSession.Token`。守护端不依赖通知监听发现 WebTV。
- WebTV 恢复时先通过 launch intent 带回前台，等待 800 ms 再发送 play，避免 WebView 留在缓冲状态。
- 云视听极光没有源码，采用“云视听在前台 + 系统媒体音频活跃”计时。暂停由全屏后台 Activity 的生命周期切换与音频焦点共同实现，不以音频焦点请求成功或媒体音量变化代替暂停结果。真机已验证音频轨停止、Home 后保持及解除后新建播放轨；该方案仍依赖当前版本实际播放器行为，第三方升级后需要重新回归。

## 关键操作

以下命令均从守护项目根目录执行，设备地址只通过参数提供，不写入仓库：

```bash
ADB=../.tools/android-sdk/platform-tools/adb
SERIAL=<电视IP:5555>

# 安装与恢复授权；保留其他无障碍和通知监听服务
python deploy/adb/init.py --serial "$SERIAL" --skip-install

# 等效遥控器：上、下、确认、返回、Home
"$ADB" -s "$SERIAL" shell input keyevent 19
"$ADB" -s "$SERIAL" shell input keyevent 20
"$ADB" -s "$SERIAL" shell input keyevent 23
"$ADB" -s "$SERIAL" shell input keyevent 4
"$ADB" -s "$SERIAL" shell input keyevent 3

# 检查当前焦点窗口
"$ADB" -s "$SERIAL" shell dumpsys window windows

# 强停测试：正常应在约 120 秒内自动恢复；超时再执行上面的 init.py
"$ADB" -s "$SERIAL" shell am force-stop com.icybard.learningguard
```

## 截图说明

普通 `screencap` 在这台 ROM 上对 Activity／无障碍答题合成层可能输出局部放大或横向裁切画面，不能据此判断实际 View 布局。Debug 构建提供仅用于验证的视图捕获，直接绘制已布局的 1920×1080 答题 View；它不是物理屏幕拍照，也不能代替家长目视确认。

```bash
"$ADB" -s "$SERIAL" shell am broadcast --receiver-foreground \
  -a com.icybard.learningguard.DEBUG_CAPTURE \
  -n com.icybard.learningguard/.DebugCaptureReceiver
"$ADB" -s "$SERIAL" exec-out run-as com.icybard.learningguard \
  cat files/validation/quiz-overlay.png > quiz-overlay.png
```

Release 构建不包含该调试截图 Action。公开截图不包含动态二维码、完整入口令牌或家长 PIN。二维码及其令牌只保留在本机忽略的验证目录，不进入文档。
